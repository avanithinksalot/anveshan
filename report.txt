1. EXECUTIVE SUMMARY
================================================================================

The prototype is a 4-layer risk-scoring system, NOT a single classifier.
Final risk comes from a deterministic hard-rule engine + an Ensemble ML layer
(Isolation Forest + XGBoost) + SHAP explanation, fused into a composite score.

Headline held-out accuracy (XGBoost supervised module, n = 9,785):
    ACCURACY  = 99.87 %
    PRECISION = 99.54 %     RECALL = 98.47 %    F1 = 99.00 %
    ROC AUC   = 0.992

IMPORTANT HONEST CAVEAT (see section 7):
This accuracy is measured against DERIVED labels (rule-engine + IF outcomes),
not against real audit ground truth, so it is OPTIMISTIC BY CONSTRUCTION.
It demonstrates that the risk surface is well-calibrated/self-consistent,
NOT that real-world fraud is caught at 99.9%. True accuracy is collected via
the Module 15 Auditor feedback loop and requires retraining on those labels.

2. MODEL STACK (per build prompt.md)
================================================================================

  Layer                    Module        What it outputs
  ------------------------ ------------- --------------------------------------
  Hard rule engine         M2-M3         2,749 deterministic violations (bypass)
  Isolation Forest         M4            per-work anomaly score [0,1] (unsupervised)
  XGBoost + SMOTE          M5            per-work risk probability [0,1] (derived labels)
  SHAP                     M6            per-work reason + global feature importance
  Text (TF-IDF+rapidfuzz)  M8            similarity_score (dup detection)
  Image (imagehash+PIL)    M9            image tamper / near-dup signal
  Composite fuse           M7            final risk_score + Low/Medium/High tier

  Composite formula (when NO hard-rule bypass):
      risk = 100 * (0.40 * isolforest + 0.40 * xgb_prob + 0.20 * avg(vendor, sim))
  Hard-rule bypass (deterministic, replaces ML):
      risk = 80 + 20 * severity(max(overdue_days/730, disallowed 0.9, ceil_ratio))
  Tiers: High >= 70 | Medium >= 40 | Low < 40

7. HONEST LIMITATIONS (do not skip this section)
================================================================================

  1. DERIVED LABELS. The XGBoost "ground truth" is built from the rule engine
     and Isolation Forest, whose outputs are ALSO model features
     (is_overdue_1yr_rule, if_anomaly_score). The model is partially predicting
     its own labels -> 99.87% accuracy is self-consistent, not real-world.

  2. CLASS IMBALANCE. Only ~5.6% positive; SMOTE re-balances training data, so
     held-out metrics reflect the balanced view. In production you would
     re-evaluate at the true prior.

  3. HARD-RULE HIGH = GUILT-FREE. A work pushed to High by the 365-day overdue
     rule is a REVIEW candidate, not a conviction. The extension band
     (365-730d) is surfaced explicitly for auditors.

  4. DATA COMPLETENESS. Several amount columns (disbursed_vs_sanctioned ratio,
     etc.) are 0% populated in the export; near-empty features are median-
     imputed and coverage is tracked so low-coverage scores can be discounted.

  5. REAL GROUND TRUTH NOT YET AVAILABLE. Until the Auditor loop generates
     verified labels at scale, "accuracy" here means pipeline calibration.

  HOW TRUE ACCURACY GETS MEASURED (built, awaiting data):
      Auditor console records cleared / escalated / confirmed decisions per
      work (Postgres audit_actions). These verified labels feed a retraining
      path that recomputes precision/recall/F1 against REAL human decisions.
      Current auditor decision volume on the live store: 7 recorded actions
      (4 escalated) — a start, not a statistically significant set yet.
